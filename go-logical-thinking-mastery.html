🧠 Go — Logical Thinking + Syntax Decoder

Problem samajhna se code likhne tak ka poora dimaag — aur har symbol (=, :, /, " ) ka exact matlab

Ye file kis problem ko solve karti hai: tumhe pata hota hai kya karna hai (logic dimag mein clear hai), par kaunsa symbol/syntax us jagah jayega — ye confusion hoti hai. Is file ka tareeka: har concept "English mein soch" se shuru hoga, phir "Go mein kaise likhenge" dikhayenge, phir wahi symbols ek decoder table mein summarize honge.

Levels

Level 1 Method Universal tareeka: Problem → Thinking → Code

Jab bhi koi problem mile, code seedha mat likhna shuru karo — pehle ye 4 sawaal khud se pucho:

1. Mujhe KYA data chahiye? → ye tumhe variables aur unka type batayega
2. Mujhe koi DECISION lena hai kya? ("agar ye condition true hai to X karo") → ye if/else/switch batayega
3. Mujhe koi cheez BAAR-BAAR karni hai? → ye loop (for) batayega
4. Mujhe is logic ko REUSE karna hai, ya ye bada hai? → ye batayega ki ek alag function banao
Example thinking: "Mujhe target list leni hai, har target pe request bhejni hai, aur agar response mein 'vulnerable' word mile to print karna hai."

Breakdown: data chahiye (target list → []string slice), decision hai ("agar word mile" → if strings.Contains(...)), baar-baar karna hai (har target pe → for loop), reuse karna hai (ek target check karna → alag function).
Yahi exact process har exploit-script, har tool, har bade program ke peeche chalta hai — sirf complexity badhti hai, method wahi rehta hai.

Level 3 Variables Kab =, kab :=, kab const

Soch: "Kya ye bilkul nayi cheez hai jo pehli baar bann rahi hai, ya already exist karti hai?"
// Naya variable — pehli baar ban raha hai
name := "Karan"          // := use hoga, type khud samajh jayega (string)

// Already bana hua variable, bas value badal rahe
name = "Karan Yadav"     // = use hoga (dobara := likhoge to error aayega)

// Kabhi badlega hi nahi (fixed value)
const MaxRetries = 5      // const use hoga

// Type explicitly batana ho (rare, zyada control chahiye to)
var age int = 18          // var + type + =
Simple rule: naya variable → :=, purana variable update → =, kabhi na badlega → const.

Level 5 Decisions If/else/switch — "agar ye to wo"

Soch: "Kya mujhe kisi condition ke hisaab se alag-alag cheez karni hai?"
if statusCode == 200 {
    fmt.Println("Target reachable")
} else if statusCode == 403 {
    fmt.Println("Forbidden — WAF ho sakta hai")
} else {
    fmt.Println("Kuch aur status:", statusCode)
}
Go mein condition ke around bracket () nahi lagta (Python/C se alag) — bas if condition {.
Jab 3+ fixed options check karne ho (ek hi variable ki alag-alag value), switch cleaner hota hai:
switch method {
case "GET":
    fmt.Println("read request")
case "POST":
    fmt.Println("write request")
default:
    fmt.Println("unknown method")
}

Level 6 Loops "Baar-baar karna hai" wala sochna

Soch: "Kya mujhe ek hi kaam multiple baar ya multiple items pe karna hai?"
// Fixed baar repeat
for i := 0; i < 5; i++ {
    fmt.Println("Attempt", i)
}

// List ke har item pe
targets := []string{"site1.com", "site2.com"}
for _, t := range targets {
    fmt.Println("Scanning:", t)
}

// Jab tak condition true ho (while-loop jaisa)
for attempts < maxAttempts {
    attempts++
}
for _, t := range targets mein _ matlab "index chahiye hi nahi, sirf value chahiye" — Level 2 ke symbol-decoder mein ye already cover hua.

Level 7 Functions Problem ko chhote tukdon mein todna

Soch: "Kya ye logic itna bada hai ki alag naam dene layak hai? Kya ye kahin aur bhi reuse hogi?"
func checkTarget(url string) bool {      // (parameter type) return-type
    resp, err := http.Get(url)
    if err != nil {
        return false
    }
    return resp.StatusCode == 200
}

// Use karna:
if checkTarget("http://target.com") {
    fmt.Println("Alive")
}
Pattern: func naam(parameter type) returnType { ... } — bracket mein jo aata hai wo "input", {} se pehle jo aata hai wo "iska output kya type hoga".

Level 8 Structs/Maps/Slices Related data organize karna

Soch: "Kya ye multiple cheezein ek hi 'cheez' ka hissa hain?" (jaise ek target ka URL + Port + Status sab saath rakhne hain)
type Target struct {
    URL    string
    Port   int
    Status string
}

t := Target{URL: "site.com", Port: 443, Status: "open"}
fmt.Println(t.URL)   // "." se field access hota hai
Struct banta hai jab tumhe lage "ye sab fields ek hi real-world cheez ka part hain" — ek target, ek user, ek request — sab struct ban sakte hain.

Level 9 Errors Go ka "if err != nil" pattern — kyu HAMESHA

Go mein koi bhi function jo "fail ho sakta hai" (network call, file read, parsing) do cheezein return karta hai: result aur error. Python/JS mein try/catch hota hai — Go mein error ko ek normal return-value ki tarah treat karte hain.

resp, err := http.Get(url)
if err != nil {
    fmt.Println("Request fail hui:", err)
    return
}
// yahan aage pahuche to matlab err nil tha, resp safe hai use karna
Rule: jab bhi kisi function se err milta hai, usi line ke baad turant if err != nil { ... } check karo — ye Go mein itna common pattern hai ki har real-world file mein 10-20 baar dikhega.

Level 10 Pointers * aur & kab use hote hain

Soch: "Kya mujhe original variable ko directly modify karna hai (copy nahi), ya bade data ko baar-baar copy karne se bachna hai?"
func increment(x *int) {   // *int matlab "int ka address lunga"
    *x = *x + 1             // *x matlab "jo address mila, uske andar ki value"
}

num := 5
increment(&num)             // &num matlab "num ka address bhejo"
fmt.Println(num)            // ab 6 print hoga — original badla, copy nahi
Bina pointer ke, Go function ko variable ka "copy" milta hai — usme changes original pe reflect nahi hote. Pointer (*, &) se "original ka address" pass hota hai, isliye andar ka change bahar bhi dikhta hai.

Level 11 Full Example English problem → final code (poori thinking ke saath)

Problem (English mein): "Mujhe 3 target URLs ki list check karni hai. Har URL pe request bhejo. Agar response status 200 ho, to 'vulnerable' print karo, warna 'safe' print karo. Jitne vulnerable mile, unka total count bhi end mein batao."
Thinking step 1: Data chahiye → URLs ki list ([]string), aur count rakhne ke liye ek number (int)
Thinking step 2: Baar-baar karna hai (har URL pe) → for loop with range
Thinking step 3: Decision lena hai (status 200 ya nahi) → if/else
Thinking step 4: "Ek URL check karna" alag reusable kaam hai → alag function banao
Thinking step 5: Request fail bhi ho sakti hai → err != nil check zaroori
package main

import (
	"fmt"
	"net/http"
)

// Step 4 ki thinking: ek target check karna alag function
func isVulnerable(url string) bool {
	resp, err := http.Get(url)      // Step 5: fail ho sakta hai
	if err != nil {
		fmt.Println("Unreachable:", url)
		return false
	}
	defer resp.Body.Close()
	return resp.StatusCode == 200   // Step 3: decision yahin return ho gaya
}

func main() {
	targets := []string{           // Step 1: data
		"http://target1.com",
		"http://target2.com",
		"http://target3.com",
	}

	count := 0                      // Step 1: count variable

	for _, url := range targets {   // Step 2: baar-baar
		if isVulnerable(url) {      // Step 3: decision
			fmt.Println(url, "-> VULNERABLE")
			count++
		} else {
			fmt.Println(url, "-> safe")
		}
	}

	fmt.Println("Total vulnerable:", count)
}
Dekho — har line ka origin ek "thinking step" se aaya, random syntax nahi tha. Jab bhi stuck ho, yahi 5 sawaal (data? decision? repeat? reusable? fail-ho-sakta-hai?) khud se pucho — code apne aap clear ho jayega.

Level 12 Logic Checklist Koi bhi code/exploit likhne se pehle ye 8 sawaal

Level 1 ka method (data? decision? repeat? reusable? fail-ho-sakta-hai?) normal programs ke liye tha. Exploit/security-tool likhte waqt isme 8 extra layers add hoti hain — ye checklist har exploit, har scanner, har automation script pe apply karo, chahe simple ho ya complex:

1. Goal clear karo — exactly kya chahiye?
"Information chahiye" (file-read, recon) ya "execution chahiye" (RCE, command-run) ya "bypass chahiye" (filter/auth todna)? Jab tak ye ek line mein clear na ho, code mat likhna shuru karo.
2. Entry point dhoondo — mera input kahan jaata hai?
URL parameter? Header (Content-Type jaisa)? Filename? Cookie? POST body field? Jitna specific pata hoga, utna chhota/sahi code banega.
3. Sink samjho — wahan pahuch ke uska kya hota hai?
Shell command ban jata hai (CI)? SQL query mein jud jata hai (SQLi)? File-path ban jata hai (LFI/traversal)? Expression evaluate hota hai (OGNL/SSTI)? Yahi decide karta hai payload ka structure kya hoga.
4. Payload design karo — us sink ko todne wala exact syntax
Sink type #3 se match karke likho — command-sink ke liye `;`/`|`, SQL-sink ke liye `'`, template-sink ke liye `{{ }}` ya `%{ }` jaisa kuch.
5. Delivery mechanism decide karo — kaise bhejna hai?
GET param? POST form? Raw header? Multipart file? Go mein ye decide karta hai kaunsa net/http function use hoga (http.Get, http.PostForm, ya manual http.NewRequest + header set).
6. Confirmation method socho — kaise pata chalega kaam kiya?
Response mein output dikhega (output-based)? Delay aayega (time-based, sleep)? Apne server pe request aayegi (out-of-band)? Bina ye socho, "kaam hua ya nahi" kabhi pata nahi chalega.
7. Automation/scale chahiye? (repeat + reusable wala Level 1 part)
Ek target pe manual test kaafi hai, ya multiple targets/payloads pe loop/goroutines chahiye? Ye decide karega function banega ya nahi, aur concurrency (goroutines/channels) ki zarurat hai ya nahi.
8. Fail-case socho — kya galat ho sakta hai?
Target down ho? Response alag format mein aaye? Filter block kar de? Har external call (http.Get, file-read) ke baad err != nil check — Level 9 wala pattern — yahi fail-case handle karta hai.
Dekho pattern: #1-3 "samajhna" hai (recon-level thinking), #4-5 "banana" hai (code-level thinking), #6-8 "verify + scale + safety" hai. Command-injection-mastery.html aur payload-library.html mein jo bhi tumne seekha, wo sab is checklist ke #1-4 ka hi content tha — ab tumhe pata hai wo content is bigger framework mein kahan fit hota hai.

Level 13 Self-Check Habit Typing karte waqt apni hi galtiyan pakadna

Jo abhi tumhare saath hua (declaration mein string likha, baad mein use mein bhi string hi type kar diya variable-naam ki jagah) — ye ek bahut common pattern hai jiska naam hai: "last-typed word repeat ho jaana" — dimaag abhi-abhi jo word type hua use hi dobara bhej deta hai, bina check kiye ki wahan uska matlab sahi hai ya nahi.

Habit 1 — Declaration ke turant baad khud se pucho: "iska NAAM kya hai?" (type nahi). Zor se bol ke ya mann mein repeat karo: "naam = name, type = string" — phir hi age badho.
Habit 2 — Line likhne ke turant baad, use aise padho jaise kisi AUR ne likha hai. Apna khud ka code fresh-eyes se padhna sabse bada debugging skill hai — jo galti likhte waqt dikhti nahi, padhte waqt dikh jati hai.
Habit 3 — Jab bhi `&variable` ya `*variable` likho, ek second ruk ke check karo: ye naam `var` line mein declare hua tha kya? Agar wo naam ek type (`string`, `int`, `bool`) hai, to galti hai.
Habit 4 — Compare karo: "jo maine socha" vs "jo maine likha". Jab confusion ho ("maine to yahi socha tha"), apna likha hua code line-by-line apne original sochne wale plan ke saath match karo — zyadatar farak 1-2 characters ka hi hota hai (jaisa tumhare case mein &name vs &string tha).
Ye sab normal hai — experienced developers bhi ye galtiyan karte hain, bas unka "fresh-eyes padhna" reflex itna fast ho chuka hota hai ki khud ko turant pakad lete hain. Practice se yahi reflex tumhara bhi ban jayega.

🧠 Mini self-check

Tumhe ek naya variable "port" banana hai jisme value 8080 rakhni hai. Kaunsa symbol use hoga: = ya :=?
:= — kyunki ye bilkul naya variable hai, pehli baar ban raha hai. port := 8080
Ek function se tumhe pata nahi kaam safalta se hua ya nahi. Konsa pattern use hoga?
result, err := someFunc() likho, phir turant if err != nil { ... } check karo — Go mein error-handling ka standard tareeka yahi hai.
Tumhe ek list ke har item pe loop chalana hai, par index ki zarurat nahi, sirf value chahiye. Kya likhoge?
for _, item := range list { ... } — _ se index ko "ignore" kar rahe ho, sirf item use ho raha hai.
Ek function ke andar tumne variable change kiya, par bahar wala original variable same raha. Kya galti ho sakti hai?
Pointer use nahi kiya — function ko normal variable diya to usne copy pe kaam kiya. Agar original badalna tha to &variable bhejna chahiye tha aur function mein *type parameter lena chahiye tha.
