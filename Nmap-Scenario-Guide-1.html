1. Decision Flow — Konsa Scan Kab

Har situation mein same command chalana galat hai. Neeche simple table hai — kis case mein kya use karna chahiye aur kyu, easy words mein.

SituationUse karoKyu (easy explanation)
Root/sudo access hai-sSSabse tez aur chhupa hua tarika, isiliye default best choice hai
Root nahi hai-sT-sS ko system-level access chahiye hoti hai, jo bina root nahi milti
Time kam hai / bahut saare targets hain-F ya --top-portsShuru mein saare 65535 ports check karna time barbaad karna hoga
Poora detailed check karna hai (jaise OSCP box)-p-Kabhi kabhi services normal se hatke port pe chal rahi hoti hain — miss karna nuksaan de sakta hai
Lagta hai IDS/IPS (security alarm) laga hai-T2 + -f + --data-lengthDheere scan karna + packet todna, dono milke alarm ko dhoka dete hain
Stable, tez lab network (HTB/OSCP)-T4Yahan chhupne ki zaroorat nahi, seedha speed pe chalo
DNS/SNMP jaisi services ka shak hai-sUYe services UDP pe chalti hain — normal TCP scan inhe kabhi nahi dikhayega
Firewall kaise kaam kar raha hai samajhna hai-sAYe sirf firewall ka behavior batata hai, port khula hai ya nahi wo nahi batata

Target Windows hai-sS -sV, -sF/-sN/-sX mat use karoWindows in scans ke tareeke ko follow nahi karta, isliye result galat aa sakta hai

2. Scenario-Based Usage

🔹 Scenario: Naya box mila, kuch pata nahi

Pehle jaldi se ek chhota scan karke andaza lo, phir dheere-dheere full port scan chalao background mein.

nmap -T4 -F target.com
nmap -p- -T4 --min-rate 1000 -oG allports.txt target.com &

🔹 Scenario: Firewall block kar raha hai, kuch response hi nahi aa raha

Nmap ko bolo ki host ko "up" hi maan le (check mat kar), phir ACK scan se firewall kaise kaam kar raha hai wo samjho.

nmap -Pn target.com
nmap -sA -Pn target.com

🔹 Scenario: Chhup ke scan karna hai, koi shor nahi machana

Teen cheezein saath mein use karo — dheera scan, packet todna, aur trusted port se bhejna.

nmap -sS -T1 -f --source-port 53 --data-length 20 target.com

🔹 Scenario: Bahut saare hosts hain internal network mein, jaldi chahiye

Pehle sirf ye pata karo konse hosts zinda hain, phir sirf unhi pe detailed scan chalao — jo hosts hain hi nahi unpe time waste mat karo.

nmap -sn 10.10.10.0/24 -oG alive.txt
grep "Up" alive.txt | cut -d " " -f2 > alive-ips.txt
nmap -T4 -sC -sV -iL alive-ips.txt

🔹 Scenario: Ek specific service ka exploit dhoondhna hai (jaise SMB)

Us service ke liye bane hue specific scripts use karo — poora general scan chalana time waste hoga.

nmap --script=smb-vuln* -p445 target.com
nmap --script=smb-enum-shares,smb-enum-users -p445 target.com

🔹 Scenario: Target ek website/web app hai

Web se related scripts aur common web ports use karo.

nmap -sV --script=http-enum,http-title,http-headers -p80,443,8080,8443 target.com

🔹 Scenario: Lagta hai koi UDP port khula hai, confirm nahi hai

UDP scan bahut slow hota hai — isliye sirf top ports tak simit rakho, poore 65535 UDP ports check karna ghanton lega.

nmap -sU --top-ports 50 -T4 target.com

3. Advanced Timing Control

-T templates ke alawa bhi kuch flags hain jinse tum speed aur timing ko aur bareeki se control kar sakte ho.

FlagYe kya karta hai (easy words)
--min-rate <n>Kam se kam itni speed pe packets bhejo — slow network mein bhi speed banaye rakhta hai
--max-rate <n>Zyada se zyada itni speed — taaki security alarm na baje
--max-retries <n>Packet miss hone par kitni baar dobara try kare (0 = sabse fast, but kabhi galat result de sakta hai)
--host-timeout <time>Ek host pe kitna waqt lagana hai max — mare hue host pe time waste nahi hoga
--scan-delay <time>Har packet ke beech thoda ruk ke bhejo — chhupne ke liye
--max-parallelism <n>Ek time pe kitne packets ek saath bhejein
Custom fine-tuned scan example
nmap --min-rate 500 --max-retries 2 --host-timeout 10m target.com

4. Advanced NSE Usage

Script categories combine karo
nmap --script "default,safe" target.com
nmap --script "not intrusive" target.com    # safe-only, production-safe
Script args pass karke brute-force NSE scripts
nmap --script ftp-brute --script-args userdb=users.txt,passdb=pass.txt -p21 target.com
Multiple specific scripts ek saath
nmap --script=smb-os-discovery,smb-enum-shares,smb-enum-users -p445 target.com
Custom script path use karna (apna khud ka .nse file)
nmap --script=/path/to/custom-script.nse target.com
--script=vuln bahut saare vulnerability-check scripts ek saath chalata hai — pura check hota hai but time zyada lagta hai. Agar time kam hai to sirf wahi CVE scripts use karo jo tumhare target pe relevant hain.

5. Advanced Evasion Tricks

Fragmentation + custom MTU combine
nmap -f --mtu 16 target.com
Decoys + randomized order (attacker ko crowd mein chhupana)
nmap -D RND:15 --randomize-hosts target.com
Bad checksum trick — kuch simple firewalls checksum verify nahi karte
nmap --badsum target.com
Append random data taaki packet size signature match na ho
nmap --data-length 50 -T2 target.com
Idle/zombie scan — poora blind scan, attacker IP kabhi expose nahi hoti
# Pehle ek zombie host dhoondo (predictable IPID sequence wala)
nmap -sI zombie-ip:port target.com
Idle scan aajkal ke networks mein kaam ka nahi rehta — ek aisa "zombie" host milna mushkil hai jiska IPID predictable ho. Ye zyada exam/theory samajhne ke liye hai, real use kam hota hai.

6. Output Chaining & Automation

Grepable output se sirf open ports extract karna
nmap -oG - target.com | grep open
XML output ko HTML report mein convert karna
xsltproc scan.xml -o report.html
Open ports ko comma-separated list mein nikaalna (agle scan mein use ke liye)
nmap -p- --min-rate 1000 -T4 target.com -oG - | grep -oP '\d+/open' | cut -d '/' -f1 | tr '\n' ','
Extracted ports ko directly deep scan mein feed karna
ports=$(nmap -p- --min-rate 1000 -T4 target.com | grep ^[0-9] | cut -d '/' -f1 | tr '\n' ',')
nmap -sC -sV -p$ports target.com

proxychains nmap -sT -Pn -p 445,3389 internal-target

8. Common Mistakes / Pitfalls

  • Sirf top-1000 ports scan karke "no vulnerabilities" bol dena — non-standard port pe service miss ho sakti hai
  • UDP scan skip kar dena — SNMP/DNS/TFTP jaisi services yahin milti hain
  • -A flag har jagah use karna — bahut noisy hai, real engagement mein IDS flag karega
  • -Pn hamesha use karna bina reason ke — slow ho jaata hai jab actually host discovery kaam kar sakti thi
  • FIN/NULL/Xmas scans Windows targets pe trust karna — unreliable results
  • Single scan pe depend karna — ek scan miss kar sakta hai, TCP + UDP + full range teeno zaroori hain thorough assessment ke liye

9. Full OSCP Recon Workflow

# 1. Quick look
nmap -T4 -F target.com

# 2. Full TCP port discovery (background/parallel)
nmap -p- -T4 --min-rate 1000 -oG allports.txt target.com

# 3. Extract ports, deep scan with scripts+version
ports=$(grep -oP '\d+(?=/open)' allports.txt | tr '\n' ',')
nmap -sC -sV -p$ports -oA deep-scan target.com

# 4. UDP top ports (parallel/background — slow hota hai)
nmap -sU --top-ports 50 -T4 target.com

# 5. Targeted vuln scripts on identified services
nmap --script=vuln -p$ports target.com

# 6. Manual verification of interesting findings
dig, curl, nc, smbclient etc. — service-specific follow-up

10. Quick Decision Cheatsheet

Root access?          → -sS         | No root → -sT
Time-limited?         → -F/--top-ports | Thorough → -p-
IDS/firewall present? → -T1/-T2 + -f  | Lab/no IDS → -T4
Need version info?    → -sV
Need OS info?         → -O (ya -A for combined, noisy)
UDP service suspect?  → -sU --top-ports 50
Windows target?       → avoid -sF/-sN/-sX, stick to -sS/-sT
Pivoted/internal?     → proxychains nmap -sT -Pn
Firewall state check? → -sA (not port state, sirf filtering behavior)
